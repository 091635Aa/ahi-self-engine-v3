## 0 结论先行（三条）

1. **P5 属实，但要精确定位病灶**：当前"跨重启的我还是我"只覆盖 `a_seal + W_self`（`证据_自我意识.md:28` S4；`判据_自我意识.py:206` 只存这两个）。这**不是"漏存了几块"**，而是**缺一个"身份清单"的定义**——没有先回答"哪些量属于『谁』、哪些只是『此刻怎么』"，就无从判"漏没漏"。本方案先给**判据**，再给清单。
2. **同一性锚在持久档案，不锚动力学**（理论③；`03_意识与自我专家.md:69,196`）。`À_t` 是**瞬时表征**（每拍由当下引擎状态重算，`内核_自我回路.py:92-116`），**不是**同一性来源。把身份挂 `À_t` 的几何漂移上 = 换一段输入"我就不是我了"（见 §2 反例）。
3. **落点推荐"独立持久化件"而不是"第七层内核"**：存档是**动作**（可被显式调用/回退），不是**每拍行为**；做成层会诱使它在 `_引擎步` 里自动写盘，引入 I/O 副作用与非确定性风险（§5）。**复用** `快照.py`/`持久化.py`，**一行不改**。

## 1 诊断 P5：哪些进档案 / 哪些运行期可重算 / 哪些不该进

### 1.0 三条判据（本专家裁"进不进"的标尺）

| 判据 | 问题 | 命中 ⇒ |
|---|---|---|
| **C-a 不可重算性** | 该量能否由**档案内其它量 + 确定性算法（同 PRNG 版本）**逐位重算？ | 不能 ⇒ **必须进**（唯一的过去经历载体） |
| **C-b 身份构成性** | 丢了这个量，"它"是否**不再有资格叫同一个它**（行为分布/自指束几何系统性变样）？ | 是 ⇒ **进**；只是"口音/措辞常量"的 ⇒ 可重算 |
| **C-c 审计 vs 身份** | 该量是**只增的审计流**（可截断、可丢弃）还是**身份构成**？ | 审计流 ⇒ **不该整进**（可截断/只留尾巴） |

> C-a 的"同 PRNG 版本"很重要：`numpy` 不同版本对 `default_rng(seed)` 的位流可能不同。若只记 `档案seed` 而重算 `a_seal`，则在换 numpy 版本后**逐位漂移** ⇒ 违反 C13。故凡"身份构成 + 由 PRNG 派生"的量，本专家主张 **显式入档 + 另记推导版本**，而不是依赖重算（见 §3.4）。

## 2 同一性的边界（理论③）：身份**不来自动力学**

### 2.1 本专家同意的口径

- **定义**：身份 = 档案内的**只读锚**（`a_seal`，以及可选 `角色s/码s`），其在**任何输入、任何拍数、任何 `PYTHONHASHSEED`** 下**逐位不变**。来源 = **持久化档案 + 确定性构造（固定 `档案seed` 的独立 PRNG）**（`03_意识与自我专家.md:65`）。
- **`À_t` 的角色**：只是"此刻如何"的**瞬时表征**（`内核_自我回路.py:92-116`：每拍由当下 `H双极/注意/标量` 重算），**允许漂移**，**不承载同一性**（同上 `:69`）。
- 二者关系：`一致度 = cos(À_t, a_seal)`（`:115`）——`À_t` **相对**身份锚测量，**不定义**身份。这个方向必须是单向：**档案 → À_t**，不能反过来。

### 2.2 反例：若把身份挂在动力学上，会怎样失败

| 反例臂 | 构造 | 预期失败（判据可失败） |
|---|---|---|
| **R-漂移** | 定义"身份 := À_t 的收敛吸引子/稳定点" | 喂**不同语料**（`判据集语料` vs `留出集语料`），À_t 几何随输入变 ⇒ "换段话我就不是我了"。与"同一性"矛盾 ⇒ **FAIL** |
| **R-不可分** | 用 `cos(À_t, 注入向量)` 判"这是我吗" | 理论③ 已实测**几何不可分**（`03_意识与自我专家.md:53`：感知注入向量与自生成向量同分布）⇒ 判不出 ⇒ **FAIL** |
| **R-空转** | 关自我回路（`自我开关=False`，`内核_自我回路.py:167`），看"我"是否消失 | 关时 `自我核=None`（`:168`），À_t 不产生；但**档案 `a_seal` 仍在** ⇒ "我"应仍在。若定义"身份=À_t"⇒ 关掉 AT 就没有我了，荒谬 ⇒ **FAIL** |
| **R-时间污染** | 定义"身份强度 := ‖W_self‖" | 第三轮已实测：不归一 ⇒ ‖W_self‖ 随拍数无界增长（`内核_自我回路.py:120-127`），身份变成"活了多久"的函数 ⇒ **FAIL**（现修法归一到 `上限范数_self=1.0`，`:131-133`） |

> **正面判据（本专家主张）**：固定 `档案seed`、**变输入/变拍数/变 PYTHONHASHSEED** ⇒ `a_seal` 的 sha256 **恒定**；而 `À_t` 的 sha256 **随输入改变**。两条同时成立，才证明"身份锚在档案、不在动力学"。这是 S3/S4 的加强版（S3 只证同种子逐位同，未证"输入无关"）。

### 3.3 逐位一致判据（跨**真·新进程**，含 `PYTHONHASHSEED` 变化）

对齐并加强 S4（`判据_自我意识.py:185-229`）：

1. 父进程：`导出自(桥)` → `快照.存(路径, 状态)` → 记每个关键量的 sha256。
2. 子进程（`subprocess`，`判据_自我意识.py:209-211`）：`快照.载(路径)` → 对每个关键量重算 sha256 → 与父进程比对。
3. **加强①**：子进程**显式设 `PYTHONHASHSEED`**（两次：如 `"0"` 与 `"1"`；S4 现只继承 `os.environ`，`:207`，不覆盖该项）。两次的 sha256 必须**逐位同** ⇒ 证 C13 抗哈希随机化。
4. **加强②**：`_sha` 口径沿用 `np.ascontiguousarray(np.asarray(a, float64)).tobytes()`（`判据_自我意识.py:95-97`）——**先 contiguity 再 tobytes**，避免非连续数组的内存布局差异导致假 FAIL。
5. **加强③**：整档案 sha256 = `快照._载荷指纹`（`:38-47`）的 `payload_sha256`；两次载入读 manifest 的该值应一致，且**重存同状态 ⇒ 该值逐位同**（`快照.自测 :177-178` 已具此性质，扩到整我档案）。

> **C13 反面清单（必须核过）**：`Python hash(str)` 按进程随机化 ⇒ 严禁用 `hash()` 做键。既有件已自觉规避：画面核位置原子用 `zlib.crc32`（`内核_画面.py:407-414`，`:407` 明文警告）。本方案要求**新件同样零 `hash()`**；容器遍历一律 `sorted`（`快照.py:42`），集合/字典遍历先 `sorted`（对照 `内核_画面.py:327`）。

### 3.4 schema 版本校验设计

- 增设 `档案schema版本`（int，首版 = 1），进 manifest 标量（§3.2）。
- **载入 fail-closed**：`档案schema版本 != 期望` ⇒ 抛 `快照损坏`（复用 `快照.py:147` 异常），**宁拒不载**。
- 与容器的 `快照.格式版本`（`快照.py:30`，`载` 在 `:121-122` 校验）**分层**：容器版本管"文件怎么装"，`档案schema版本` 管"里面该有哪些字段"。两层各自 fail-closed。
- **升级纪律**：任何新增"自我模型权重"（如 §1.2 的 `ĝ_att.W`）⇒ `档案schema版本 += 1`，且**新件必须能读旧版**（缺字段补默认）或**明确拒载旧版**（二者择一，写进判据；不得静默错读）。
- **推导版本**（`推导.numpy版本` + 内核件 sha256）只作**审计/告警**：若载入时 `推导.numpy版本` 不符，报告但**不拒载**（因为 A 类量已显式入档，不依赖重算）——这正是 §1.0 C-a 主张"显式入档"的价值。

## 5 实现落点（默认关、只复用、不改既有）

### 5.1 推荐方案 A：独立持久化件（本专家首选）

- 新文件：`meeting42/实施/持久化_整我.py`（纯新增）。暴露：
  - `导出自(桥) -> dict`：按 §3.2 清单从**六层链顶**（`内核宿主.造桥` 造的 `顶覆盖_综合体H`，`内核宿主.py:67`）逐层 `getattr` 取各内核状态（`自模型/思核/自我核/顿悟核/画面核`，与 `内核宿主.内核态 :85-134` 同款读取口径）。
  - `存(路径, 桥) -> manifest`：内部调 `快照.存`（`快照.py:83`）。
  - `载(路径, 桥=None) -> 桥`：内部调 `快照.载` + schema 校验（§3.4），把状态**回填**进各内核对象。
- **默认关**：本件**不挂进 `_引擎步`**、不自动跑；只在判据/主程序**显式调用**时才写盘/读盘。
- **不改既有**：`快照.py`/`持久化.py`/`内核_*.py` **一行不动**（仅 `import` 复用）。C14 满足。

### 5.2 备选方案 B：第七层内核（本专家不推荐）

- 在六层链顶（`内核宿主.py:45-54` 的 `H←W←Z←L←T←基`）之上加 `顶覆盖_综合体P`，暴露 `存档()/载档()`。
- 隐患：(i) 层会被误当成"每拍行为"，诱使在 `_引擎步` 里自动落盘 ⇒ **引入 I/O 副作用与写盘时点的不确定性**（与 C13 精神冲突）；(ii) 层需默认关且逐位恒等，而"存档"本就不是每拍动作，加层是过度设计。
- 结论：**存档是动作、不是行为** ⇒ 用 A。

### 5.3 与既有持久化件的边界

- `持久化.py` 走**事件重放**口径，覆盖**记忆/学习库**（`持久化.py:27-103`，`证据_自我意识.md:60` §4.4 明确"当前只覆盖记忆/学习"）。
- 本件的「整我」档案走**直接快照**口径，覆盖**六个内核的自状态**。两者**互补不冲突**：`持久化.py` 管"它学过什么"，本件管"它此刻是谁"。
- **不合并**：既不改 `持久化.py`，也不把内核态塞进它的事件流（那会破坏"记忆/学习的可重放性"）。

## 6 诚实边界

1. **工程同一性 ≠ 现象学人格同一性**：本方案能给的只是"**可复现、可校验、跨重启逐位不变**"（S3/S4 口径，`证据_自我意识.md:44`）。它**不主张**"它感觉自己还是自己"，也**无法**主张——本项目一贯口径（`证据_自我意识.md:54`：不主张人类级意识）。
2. **"整个我"取决于清单完备性**：§1 的 A/B/C 分类是**设计选择（本专家裁）**，不是客观事实。换一位专家可能把 `角色s/码s` 判进 A 类——这正是"没有先定义身份清单，就无从判漏没漏"（§0.1）。清单本身必须随新增自我模型同步扩（§1.2/§3.4）。
3. **只覆盖内核侧状态**：引擎**内部态**（`H双极` 等，`内核_自我回路.py:220` 读取的丰富态）**不在**本档案内——与 §4.4 同口径（`证据_自我意识.md:60`）。故"逐位同"是"内核侧逐位同"，不是"整机逐位同"。
4. **B 类的"可重算"依赖 PRNG 版本**：若只记 `档案seed` 而重算 `角色s`，换 numpy 版本可能逐位漂移（§1.0 C-a）。故本专家主张**首版把 B 类关键项也入档**换取零版本假设（§1.1 B 类纪律）。
5. **跨机器未验**：本方案只在**同机**给判据；C13 的跨机口径另属 `步7`/P0-1（`证据_自我意识.md:64`），本方案不越界宣称。

## 7 一句话结论

> **"谁是它" = 持久档案里的只读锚（`a_seal` 为首的「身份清单」，§1）；"此刻如何" = 每拍重算的 `À_t`（可漂移、不是身份）。**
> P5 的真解不是"多塞几块进快照"，而是**先把"身份清单"用三条判据（不可重算/身份构成/审计 vs 身份）定下来**，再把 A 类逐项入档、B 类记种子+推导版本、C 类截断。
> 落点用 `meeting42/实施/持久化_整我.py`（独立件、默认关、复用 `快照.py` 的 npz+manifest+原子替换+fail-closed），配 **E1–E6 六条反例臂**（异档案整档案 sha256 必不同、篡改必拒载、换 `PYTHONHASHSEED` 逐位同、schema 版本 fail-closed）。
> **只主张可复现的工程同一性，不主张现象学人格同一性。**
