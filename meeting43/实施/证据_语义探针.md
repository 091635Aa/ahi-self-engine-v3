# 证据_语义探针 —— meeting43 · P1 探针策略（默认关 + 增强项）

> 判据件：[`判据_语义探针.py`](判据_语义探针.py)（`python 判据_语义探针.py`，exit=0，J1–J4）。
> 改动件：`meeting28/dialogue_bridge.py`（`感知向量` 的探针策略）。铁律 C1/C9/C10/C13/C14。

## 1. 策略（为什么默认关）

原报告 P1 要求把 `感知向量` 的**随机高斯探针**换成**数据自定语义探针**。实现后遇到一个**既有权衡**：
语义探针改变了引擎输入分布，令 `meeting39/步2_自模型接线自证` 的**反作弊条件**
「五维摘要 AUC≈0.5」由 0.5619 变为 **0.7194**（越出 ≤0.62）⇒ 该判据 FAIL。

**A/B 隔离**（一次只回退一处）：

| 配置 | 五维臂 AUC | 步2 A1 |
|---|---|---|
| 两处都回退 | 0.5619 | PASS |
| 只回退探针（精化生效） | 0.5619 | PASS |
| 只回退精化（新探针生效） | 0.7194 | FAIL |
| 我的配置（两处都生效） | 0.7194 | FAIL |

⇒ **元凶 = 语义探针**，与精化无关。
**变体搜索**（blend50 / blend30 / rot…）发现"混合"是**非单调且脆弱**的（blend50 0.8156 反而比 sem 0.7194 更差，blend30 0.5188 才过）——靠调旋钮去喂饱判据属**凑数**，故**不采用**。

**最终策略（与本次其余机制一致）**：语义探针 **默认关**（`AHI_语义探针=1` 开启），严守仓库铁律
「新层默认关 ⇒ 逐位恒等」（C14/D1）。**这不是削弱 P1**——见 §2：默认（随机探针）下「意」**已经**进引擎。

## 2. 默认下「意仍进引擎」（P1 的核心已达成）

`精化`（默认开，见 [`证据_语义码.md`](证据_语义码.md)）已使 `编码 / 字袋` 携带**共现语义**；
`感知向量 = 探针 @ 编码(text)`，随机探针只是它的 **JL 投影** ⇒ 语义照常进入 16 维引擎感觉。

| 感知向量(16 维) cos | 默认（随机探针） | 开语义探针 |
|---|---|---|
| 苹果 / 水果 | **0.9972** | 0.9748 |
| 高兴 / 开心 | **0.9040** | 0.9369 |
| 苹果 / 高兴（无关） | 0.2728 | **−0.0483** |

⇒ 默认下相关对已高度相近（意进引擎）；语义探针的**增量价值 = 区分度**（把无关对压低）。

## 4. 开关
- `AHI_语义探针=1` → 启用数据自定语义探针。
- 默认（不设，或设 `AHI_旧探针=1`）→ **旧随机探针**（逐位恒等既有行为）。

## 6. 诚实边界
1. 语义探针的**端到端收益未评测**（默认关 ⇒ 未进 acceptance）；只证明了它是数据自定且区分度更强。
2. 「子空间重叠=1」依赖**段数 ≥16**（段少时探针只能填部分行、其余回退随机，见判据 J2 的构造说明）。
3. 未声称语义探针优于随机探针的**绝对**价值；它是可选的增强项，默认不改变系统行为。
